# Tozo Security SDK 验证报告 v0.0.9

日期：2026-08-30
对应 SDK 状态：配置精简完成后（v0.0.9）
上一版本：本报告取代 `docs/test-reports/` 下 16 份历史报告

## 0. 本报告的取代关系与写法说明

原先 `docs/test-reports/` 下有 16 份报告，其中 6 份是相互重叠的汇总报告。
它们已被本报告整体取代，原因不是「过时」这么简单，而是**其中的关键结论已经错了**：

| 历史报告中的表述 | 实际情况 |
|---|---|
| 「响应完整性验证逻辑未实现」列为已知问题 | 早已实现，`ResponseIntegrityClosureTest` 18 个用例覆盖 |
| 引用 `tests/Tozo/Security/` 路径 | 该路径不存在，实际是 `tests/Unit/` 与 `tests/Integration/` |
| 「单元测试覆盖率 92% / 95%」等百分比 | **无法核实**：项目未配置覆盖率工具，`composer test` 走 `--no-coverage` |
| 运行环境「PHP 8.1+」 | 实际基线是 PHP >= 7.4，生产用 7.4.3 |
| 「版本 0.1.0」 | `composer.json` 未声明 version |

因此本报告**只写可由命令复现的数据**，不写覆盖率百分比。
任何一行结论都能用文中给出的命令在当前 checkout 重跑得到。

## 4. 本轮修复的缺陷

三个都是真实缺陷，不是「为通过测试而调整」。

### 4.1 FileKeyProvider 启动死锁

`FileKeyProvider` 在构造器里 realpath 校验密钥目录，而该目录由 `tozo:security:install`
命令创建。全新安装时 artisan 因目录缺失而无法启动，那条创建目录的命令就永远跑不起来。

修复：目录存在性校验从构造期移到检索期，缺失时抛 `KeyNotFoundException`，
使 `check-config --runtime` 能列出完整错误清单而不是直接崩掉。

### 4.2 目录穿越防护的路径形态不一致

上一项修复引入的连带缺陷。惰性化后 `keyDir` 不再是 realpath 结果，
而穿越防护用它与 realpath 后的文件路径做前缀比较——两侧形态不同（分隔符、符号链接），
比较必然失配，**合法密钥被误判为穿越攻击**。

修复：检索期对两侧同时做 realpath 规范化后再比较。
由 `KeyProvidersTest::test_file_provider_reads_key_and_rejects_traversal` 锁死。

### 4.3 示例控制器的三处代码缺陷

配置精简前的手写示例包中，`TozoSecurityController.php` 存在：
`'health' => 'ok'` 重复 33 次（PHP 数组重复键，后者静默覆盖前者）、
`return` 之后的不可达代码、末尾 `return` 引用未定义变量。
8 套示例每套都有这个文件。

修复：v0.0.9 示例包由 `tools/gen_examples.php` 生成，从源头消除手写不一致。

### 4.4 命名空间引用批量损坏（非代码缺陷，属操作事故）

一次 IDE 移动操作把 54 个 PHP 文件与 10 个文档的 `use` 语句改写成
`Tozo\Security\Audit\src\Tozo\Security\*` 这类不存在的路径，
另有 3 处 `use` 被折叠成单行、50 个文件缩进被改成 Tab。已全部还原。

判定依据：`src` 在 PSR-4 下永远不可能是命名空间片段；且会话早期
`ConfigNormalizer` 相关脚本能正常运行，证明损坏发生在那之后。

## 5. 关键安全行为的测试锚点

下表列出「这条安全约束由哪个用例锁死」，便于改动时判断影响面。

| 安全约束 | 锁死它的用例 |
|---|---|
| 算法只由 Profile 决定，绝不读 Token Header 的 alg | `TokenAlgorithmConfusionTest`（7 个，含正向对照） |
| 响应密钥不得复用请求密钥 | `ProfileValidationTest` + `ResponseIntegrityClosureTest` |
| 12 条有向关系两端推导出的密钥必须一致 | `ConfigNormalizerTest::test_four_systems_derive_symmetric_keys_for_every_relation` |
| 两个环境不共用任何密钥 | `ConfigNormalizerTest::test_environments_share_no_key_material` |
| 已存在的密钥绝不被覆盖 | `SecurityInstallCommandTest::test_existing_keys_are_never_overwritten` |
| 未声明的对端必须明确拒绝，不回退 | `FreshInstallTest::test_routing_to_an_undeclared_peer_fails_loudly` |
| 默认安装只验证不签发 | `ServiceProviderTest` + `ConfigNormalizerTest::test_features_are_derived_from_actual_profile_usage` |
| 防重放 TTL 必须覆盖完整接受窗口 | `HmacSignerTest` + `SharedStateIsolationTest` |
| 共享 HttpClient 不产生 Profile 污染 | `SharedStateIsolationTest`（7 个） |
| 加密体积上限把 fatal OOM 转为可捕获异常 | `PayloadSizeGuardTest`（7 个） |
| 目录穿越被拒绝 | `KeyProvidersTest::test_file_provider_reads_key_and_rejects_traversal` |
| 签名 query 以线上原始字节为唯一事实来源 | `ProtocolCanonicalizationTest` + `Integration/QueryInteropTest` |

## 6. 不能因本报告全绿而视为已证明的事项

这一节是本报告最重要的部分。**测试全过不等于可以上生产。**

| 项目 | 当前状态 |
|---|---|
| PHP 7.4 语法与运行时 | **已验证**：当前 checkout 在 7.4.3 跑通全部八项 |
| Protocol v1 固定向量 | **已验证**：70 条冻结并经三语言独立复核 |
| JWT 算法混淆防护 | **已验证**：7 个负向用例 + 正向对照 |
| 跨语言一致性 | **已验证**：Python 3.9.13 与 Go 1.25.7 独立实现逐字节一致 |
| 完整 Laravel 8.5 应用 | **未验证**：HTTP Kernel、路由参数、中间件 alias、`config:cache`、package discovery |
| Redis 多实例原子性 | **未验证**：`SET NX` 原子性、TTL 精度、网络故障传播、并发压测 |
| 真实 HTTPS 传输 | **未验证**：Guzzle、TLS 握手、代理、超时、4xx/5xx、响应头归一化 |
| 网关行为 | **未验证**：WAF / API 网关是否改写 Body 或剥离 `X-Tozo-*` 头 |
| 生产密钥管理 | **未验证**：Vault/KMS 下发、权限、轮换、备份、泄露响应 |
| 高并发性能 | **未验证**：签名与加解密吞吐、Cache 争用、大 Body 内存 |
| 不停机密钥轮换 | **存在已知缺口**：轮换状态机只有 `ArrayKeyProvider`（仅测试）支持注入状态，生产用的 `FileKeyProvider` 全部视为 `active`，因此当前轮换需要停机窗口。详见生产部署手册 §10.1 |
| 业务适用性 | SDK 不能替项目方判断某条路由是否适合 `token_only` |

### 6.1 注释深度审查工具的局限

`composer audit-depth` 报零未达标，但该工具**只能度量说明的字数**，
无法判断说明是否真的回答了「为什么是这个值、违反会怎样」。
字数达标不等于内容达标——它是下限门禁而非上限保证，人工审阅不可省略。
