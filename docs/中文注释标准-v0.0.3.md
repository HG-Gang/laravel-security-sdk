# 第三方鉴权中文注释标准

版本：v0.0.3
修订日期：2026-08-28
上一版本：v0.0.2（2026-08-21）

## 0. 本版修订说明

v0.0.3 在 v0.0.2 基础上补充三类硬性要求，并把全部要求变为**机器可校验**：

| 新增要求 | 校验入口 |
|---|---|
| 每个文件必须有 PhpStorm 头部标识块 | `composer run headers-check` |
| 每个类属性与类常量必须有中文注释 | `composer run audit-members` |
| 每个配置键必须有中文说明 | `composer run audit-members` |

同时明确：**注释只写类型不算达标**。`@var string` 这类纯类型声明不构成说明，必须补充"是什么、为什么存在、边界在哪"。

原 v0.0.2 全部条款继续有效，本版为增补而非替换。

## 1. 目的

统一第三方鉴权相关 PHP、配置、路由、测试和文档的中文注释。注释必须帮助维护者理解"为什么这样处理、边界在哪里、失败时为什么不能继续"，不能只是把代码翻译成中文。

本标准参考 `app/Common/S3UploadGateway.php` 的方法内阶段注释风格，并补充认证代码特有的安全边界要求。

## 2. 适用范围

- 鉴权策略、管理器、结果对象和异常。
- 路由、中间件、控制器、请求解析器。
- 调用方 HTTP Client 和调试入口。
- 配置文件、测试文件和接入文档。
- 其他涉及密钥、签名、防重放、白名单、脱敏和业务入参桥接的代码。

## 3. 注释层级

相关文件按实际复杂度使用**五层**注释（v0.0.3 新增第 1 层）：

1. **文件头部标识层**：PhpStorm 头部块，标注项目、作者、创建日期时间。
2. 文件级：文件职责、输入、输出、明确不负责的内容。
3. 方法级：方法目的、参数、返回、异常和安全语义。
4. **成员级**：类属性与类常量的含义、约束、为什么是这个值。
5. 方法内部阶段级与关键行级：说明一组代码当前解决什么问题。

简单 getter 或一眼可知的赋值不强制补方法内部注释；复杂安全流程不能只写 PHPDoc 而没有阶段说明。

但第 1、4 层**没有例外**：所有文件都要有头部块，所有属性与常量都要有中文注释。

## 4. 文件头部标识块（v0.0.3 新增，强制）

### 4.1 固定格式

每个文件开头必须有如下标识块。PHP 文件中位于 `<?php` 之后、文件级功能说明 PHPDoc 之前：

```php
<?php

/**
 * Created by PhpStorm.
 * Project name Tozo-security-sdk-php.
 * User: Huang Gang
 * Date: 2026/08/28
 * Time: 01:10
 */

/**
 * SystemClock
 *
 * 文件功能：
 * - ClockInterface 的系统时钟实现
 */

namespace Tozo\Security\Clock;
```

字段含义：

| 字段 | 内容 | 说明 |
|---|---|---|
| `Project name` | 项目名 | 与仓库目录名一致 |
| `User` | 作者 | 文件创建者 |
| `Date` | `yyyy/mm/dd` | 创建日期 |
| `Time` | `HH:mm` | 创建时间，24 小时制 |

### 4.2 与文件级注释的关系

两块**都要有，且顺序固定**：标识块在前，功能说明在后，中间空一行。

标识块只回答"谁在什么时候创建了这个文件"；它**不替代**文件级功能说明。只有标识块没有功能说明，属于不达标。

### 4.3 非 PHP 文件

协议一致性实现等非 PHP 文件使用各语言的注释语法承载同样字段：

```python
# Created by PhpStorm.
# Project name Tozo-security-sdk-php.
# User: Huang Gang
# Date: 2026/08/28
# Time: 01:10
```

```go
// Created by PhpStorm.
// Project name Tozo-security-sdk-php.
// User: Huang Gang
// Date: 2026/08/28
// Time: 01:10

package main
```

Go 的标识块必须在 `package` 声明**之前**。

### 4.4 批量插入与校验

```bash
php tools/add_file_headers.php          # 为缺失文件插入（幂等，已有的跳过）
php tools/add_file_headers.php --check   # 只报告缺失，不修改（CI 使用）
```

工具保持 LF 行尾与无 BOM 的 UTF-8 编码——签名规范化串以 `\n` 连接，CRLF 会破坏跨平台字节一致性。

## 5. 类属性与类常量注释（v0.0.3 新增，强制）

### 5.1 只写类型不算达标

这是本版最重要的一条。以下写法**不合格**：

```php
/**
 * @var string
 */
private $clientId;
```

`@var string` 只说明了 PHP 类型，没有说明这个字段是什么、参与什么流程、有什么约束。维护者读完仍然不知道能不能改它。

合格写法：

```php
/**
 * 调用方唯一标识。参与签名原文与 AEAD AAD 的绑定，
 * 同时作为入站 Profile 候选查找的不可信索引依据。
 *
 * @var string
 */
private $clientId;
```

`@var` 保留（IDE 与静态分析需要），但中文说明是必需部分。

### 5.2 常量必须解释"为什么是这个值"

常量的字面量往往就是协议约定，注释必须写清约束来源与违反后果：

```php
/**
 * 对称密钥字节长度，固定 32（AES-256）。
 * KeyProvider 返回的是环境变量字符串原文，因此校验的是 strlen 而非解码后长度；
 * 长度不符即抛配置异常，防止误配短密钥静默降级为更弱强度。
 */
public const KEY_BYTES = 32;
```

```php
/**
 * GCM nonce 字节长度，固定 12（96-bit，NIST SP 800-38D 推荐值）。
 * 每次加密由内部 CSPRNG 重新生成，API 不接受外部注入。
 */
public const NONCE_BYTES = 12;
```

不合格：

```php
public const KEY_BYTES = 32;              // 无注释
public const NONCE_BYTES = 12;            // 12 bytes ← 纯英文且只复述字面量
```

### 5.3 枚举型常量说明业务语义差异

同一族常量的注释必须让人看懂**彼此的区别**，而不是各写一遍名称：

```php
/**
 * 轮换状态：当前主用密钥。读写两个方向的全部用途都允许。
 */
public const STATE_ACTIVE = 'active';

/**
 * 轮换状态：只读迁移期（签名类）。可用于验签，但绝不可再生成新签名。
 * 用于 HMAC 共享密钥或 JWT 公钥的短迁移窗口。
 */
public const STATE_VERIFY_ONLY = 'verify_only';

/**
 * 轮换状态：已退役。任何用途都必须拒绝，不允许任何"兼容性"例外。
 */
public const STATE_RETIRED = 'retired';
```

### 5.4 默认值属性说明"为什么可以有默认值"

```php
/**
 * Nonce 保留秒数。默认 425 = 300 + 2×60 + 5（对应 SDK 默认时间窗）；
 * 实际值由 Signer 在 record() 前按 Profile 的窗口公式覆盖，
 * TTL 必须覆盖完整接受窗口，否则合法重试可能被误判或重放窗口出现空隙。
 *
 * @var int
 */
private $ttl = 425;
```

### 5.5 依赖注入属性说明"为什么需要这个依赖"

```php
/**
 * 缓存仓储。必须是所有服务实例共享的后端（Redis 等）：
 * 进程内数组或单机文件无法提供跨实例的"只写一次"语义，多实例部署会漏放重放请求。
 *
 * @var CacheRepository
 */
private $cache;
```

### 5.6 测试中的匿名类属性同样要求

测试替身的属性也在范围内，说明它为什么存在：

```php
return new class($timestamp) implements ClockInterface {
    /**
     * 固定的 Unix 秒级时间戳。让 iat/nbf/exp 判定完全可复现，
     * 避免用例因真实时间流逝而间歇性失败。
     *
     * @var int
     */
    private $ts;
```

### 5.7 校验

```bash
composer run audit-members
```

判定口径：属性/常量声明前必须紧邻注释块（中间只允许空白与可见性修饰符），且注释含中日韩统一表意文字。

同一口径由 `tests/Unit/MemberCommentCoverageTest.php` 纳入 CI 门禁——新增属性忘写注释会在 `composer run test` 时立即失败。

## 6. 配置文件注释（v0.0.3 强化）

### 6.1 每个键都要有说明，段级键也不例外

v0.0.2 已要求"配置项要写清默认值、安全含义、单位和失败行为"，但实践中容易漏掉**段级键**——说明写在分隔线上方的整块注释里，键本身没有说明：

```php
// ------------------------------------------------------------------
// 应用级功能开关：未开启的功能不注册容器绑定。
// ------------------------------------------------------------------
'features' => [        // ← 这个键自己没有说明，不达标
    // authentication bool｜是否启用认证器绑定。示例：true
    'authentication' => true,
],
```

合格写法——段级键补自己的行内说明：

```php
// features array｜应用级功能开关总表。有效能力 = 本开关为 true 且至少一个 Profile 引用该功能。
'features' => [
    // authentication bool｜是否启用认证器（jwt / hmac_bearer_sha256）绑定。示例：true
    'authentication' => true,
],
```

### 6.2 推荐的键说明格式

```text
// {键名} {类型}｜{含义}。{约束与失败行为}。示例：{值}
```

```php
// max_age_seconds int｜签名最大年龄（秒）；超出 max_age+skew 窗口拒绝。示例：300
'max_age_seconds' => 300,

// key_id string｜32 字节对称密钥标识（enabled=true 必填）。
// 环境变量：TOZO_SECURITY_KEY_TOZO_SERVICE_ENCRYPTION。示例："tozo-service-encryption"
'key_id' => env('TOZO_SECURITY_ENCRYPTION_KEY_ID', 'tozo-service-encryption'),
```

### 6.3 配置文件必须包含快速开始

配置模板必须让接入方不靠试错就能启用。文件末尾附启用步骤：

```php
/*
|--------------------------------------------------------------------------
| 快速开始（最小可用出站配置）
|--------------------------------------------------------------------------
|
| 1. 生成并注入密钥：php artisan tozo:security:make-key
| 2. 在 .env 启用模板 Profile 并指定默认出站目标
| 3. 体检：php artisan tozo:security:check-config --runtime
|
*/
```

### 6.4 模板配置必须自洽且可启动

配置模板中的各项开关组合必须**自身无矛盾**。若模板声明的 `security_mode` 要求某个功能而该功能默认关闭，接入方启用模板时会连环撞配置错误。

要求：模板 Profile 默认 `enabled = false`（保证装上即可启动），且把 `enabled` 改为 `true` 后不应出现第二个配置错误。

不要在注释中放真实配置值，也不要写"这里填生产密钥"等容易被复制进仓库的示例。

## 7. 方法级注释

方法级 PHPDoc 至少回答：

- 方法做什么。
- 参数来自哪里、类型是什么。
- 成功返回什么。
- 失败是返回错误、抛异常还是失败关闭。
- 非显而易见的安全约束。

```php
/**
 * 原子登记已验签 token，拒绝同一 token 重复执行。
 *
 * @param string $partnerCode 路由已解析的第三方标识。
 * @param array $attributes 验签策略返回的安全元数据。
 * @return void 首次登记成功时无返回值。
 *
 * @throws PartnerAuthException token 已消费、元数据错误或 Cache 不可用时抛出。
 */
```

`@param` 必须覆盖全部签名参数，非构造器方法必须有 `@return`。由 `composer run audit-style` 校验。

不要给每个私有一行方法机械添加"获取 X""返回 X"而没有任何额外信息。如果方法名、类型和 return 已完全表达含义，可以保持简短。

## 8. 方法内部行级注释

（本节内容与 v0.0.2 第 6 节一致，此处保留要点）

### 8.1 方法开头：说明当前阶段目标

```php
// 先验证 token 绑定的原始 body 和请求上下文，避免未认证请求获得 payload 校验细节。
$authResult = $manager->authenticate(...);

// 验签完成后再登记一次性 token，确保重放请求不会进入业务。
$this->assertAuthorizationNotReplayed(...);
```

### 8.2 分支前：解释为什么判断

```php
// Cache 无法确认 token 是否已使用时必须失败关闭，不能以"可用性优先"为由放行业务。
try {
	$accepted = Cache::add($key, true, $ttl);
} catch (Throwable $exception) {
	throw $this->replayStorageUnavailable();
}
```

### 8.3 关键转换前：写清数据来源和信任边界

```php
// 只使用中间件写入的已验签 payload；不从普通 input/query 重新取值。
$payload = $request->attributes->get('third_party_payload', []);

// query 不参与当前签名，委派旧业务前必须清空，避免未签名参数混入 request->all()。
$request->query->replace([]);
```

### 8.4 catch/finally 前：说明失败关闭或资源释放意图

```php
} catch (Throwable $exception) {
	// 下游状态未知时不伪造成功；统一转成网络失败并保留原异常链。
	throw new RuntimeException('第三方调试请求失败', 0, $exception);
}
```

### 8.5 相邻注释的粒度

一条阶段注释可覆盖接下来的 2～8 行同一目的代码；当下一段目的改变时再写一条。不要让每一行代码前都有一条同义注释。

## 9. 测试注释

测试名优先表达行为。只有数据提供器、复杂测试替身或安全意图不明显时补注释。

正确：

```php
public function test_calculate_traffic_fails_closed_when_replay_store_is_unavailable(): void
```

失败测试中的注释应说明"为什么必须失败"，不要把预期实现步骤写成注释。

但测试文件的**头部标识块**与**类成员注释**同样强制（见第 4、5 节）。

## 10. 统一语言与格式

- 中文优先，类名、方法名、协议字段和标准术语保留英文。
- `token`、`payload`、`raw body`、`Header`、`Cache` 在同一文件内写法一致。
- 参数注明单位，例如秒、毫秒、字节。
- 注释使用当前事实和现在时，不写过期迁移过程。
- 一行注释尽量不超过项目现有可读宽度；复杂说明放 PHPDoc 或 Markdown。
- 注释与代码冲突时，以代码和测试为准，并立即修正文档，不能保留"双口径"。
- 源码统一使用**空格缩进**，不使用 Tab；由 `composer run audit-style` 校验。
- 文件统一为**无 BOM 的 UTF-8**、**LF 行尾**。BOM 会在 Laravel 中产生提前输出破坏 `header()`；CRLF 会破坏签名原文的跨平台字节一致性。

## 11. 注释的完整判断标准

一个复杂方法的注释完整性可以用下面这张表自检：

| 检查项 | 必须能回答的问题 |
|---|---|
| 输入来源 | 数据来自 Request、配置、Cache、旧接口还是服务端内部状态？ |
| 信任边界 | 哪些值不能直接信任？哪些值已经经过校验？ |
| 转换原因 | 为什么要 trim、lowercase、重新命名或重新组装？ |
| 分支语义 | 各分支分别代表什么业务含义？ |
| 默认值 | 为什么可以生成默认值？默认值是否改变安全或业务含义？ |
| 失败行为 | 为什么这里抛异常、返回原结果或允许继续？ |
| 并发语义 | 为什么加锁、为什么先写状态、为什么拒绝重复执行？ |
| 兼容性 | 哪些字段/结构只是历史兼容？真正权威的数据是什么？ |
| 生命周期 | stream、临时文件、锁、远端会话由谁创建、谁释放？ |
| 返回值 | 返回字段为什么这样映射？哪些字段只服务旧调用方？ |

类成员补充自检：

| 检查项 | 必须能回答的问题 |
|---|---|
| 存在理由 | 这个字段/常量为什么需要存在？ |
| 取值约束 | 为什么是这个值/长度/默认值？违反会怎样？ |
| 参与流程 | 它在哪个环节被读写？ |
| 同族差异 | 与同一族的其他常量区别在哪？ |

## 12. 机器校验总表

全部要求都可自动校验，不依赖人工审阅：

| 命令 | 校验内容 |
|---|---|
| `composer run lint` | 全量 `php -l` 语法检查 |
| `composer run audit-style` | 方法级 PHPDoc 完整性、`@param`/`@return` 覆盖、BOM、Tab、孤立注释块、未使用导入 |
| `composer run audit-members` | 类属性/常量与配置键的中文注释覆盖 |
| `composer run headers-check` | 文件头部标识块覆盖 |
| `composer run test` | 上述规则的测试化门禁（含 `MemberCommentCoverageTest`、`FileHeaderTest`） |
| `composer run verify` | 以上全部 |

**注释规则以工具输出为准。** 人工判断"看起来注释挺多"不构成达标依据。

## 13. 最终原则

中文代码注释的目标不是让代码"看起来注释很多"，而是让维护者在不打开旧实现、不追完整调用链的情况下，仍然能回答：

```text
这个数据从哪里来？
为什么要这样转换？
谁的数据可信？
为什么这里必须失败？
为什么这里可以继续？
这个字段为什么还要保留？
这个状态为什么不能重复执行？
这个临时资源什么时候释放？
这个常量为什么是这个值？
```

对于复杂业务适配器，优先解释**业务意图、兼容边界、安全边界、状态变化和失败语义**；不要把注释写成 PHP 语法的中文翻译。
